# Arquitectura y límites

- **Datos inmutables:** NPZ y CSV versionados en `research/`, métricas y entradas en el NPZ compacto; checkpoints de investigación conservados aparte según `research/ORIGEN.md`; referencias y hashes en `web/data/manifest.json`. Persistencia científica basada en archivos de sólo lectura durante la ejecución, versionable con Git; no requiere base externa.
- **Núcleo en navegador:** selección, reproducción, proyección Canvas 3D, inspección y verificador estructurado. No se interpola para crear observaciones. Este núcleo funciona servido estáticamente en GitHub Pages, sin servidor de IA.
- **Backend opcional local:** `server/server.py` y `lab.py` ofrecen JSON `status.v1`, `verification.v1` y `agent_response.v1`. La capa científica lee NPZ; la orquestación invoca uno o tres roles secuenciales, aportando las propuestas previas como material explícitamente no verificado. El verificador numérico ejecuta código; no es otro LLM. Las respuestas LLM se etiquetan como no verificadas y se avisa si son casi idénticas. No se permite al modelo ejecutar herramientas, modificar archivos ni cambiar la selección del alumno.
- **Proveedores:** Transformers local o API local de Ollama fija en 127.0.0.1. No se implementa proveedor comercial ni se reciben claves; no almacenar secretos en el navegador o repositorio. Máximo 1.000 caracteres de mensaje, 8 mensajes de historial aceptados (se envían hasta 4 al modelo), hasta 256 tokens de salida por rol y 4 turnos/minuto por proceso por defecto. Tres roles implican tres inferencias secuenciales. Un bloqueo serializa generación. Los límites no son un sistema distribuido de cuotas ni defensa integral ante abuso.
- **Memoria:** selecciones en localStorage del navegador, una clave que el estudiante puede borrar. Historial de conversación sólo en memoria de la pestaña, máximo 8 mensajes; se pierde al recargar. El servidor no persiste conversaciones (los logs HTTP pueden incluir ruta y dirección, no cuerpo). La petición de chat incluye texto e ID de selección al servidor. Si el proveedor Transformers descarga pesos, Hugging Face recibe tráfico de descarga. No se necesita cuenta en la app. No enviar secretos, información sensible ni datos personales de menores.
- **Seguridad:** servidor por defecto escucha sólo `127.0.0.1`, IA desactivada salvo opt-in. Comprueba Origin cuando se envía, tipo JSON, tamaño y contratos. No tiene autenticación, aislamiento multiusuario, TLS propio, protección de gasto ni límite distribuido. **No exponer el backend a Internet** sin autenticación, TLS, protección CSRF, cuotas y revisión de seguridad. El preview de Arena escucha 0.0.0.0 únicamente para la demostración efímera; no es un despliegue de producción.

## Limitación importante del ensayo real

Se ejecutó una conversación con tres llamadas a `HuggingFaceTB/SmolLM2-135M-Instruct` local (revision `12fd25f77366fa6b3b4b768ec3050bf629380bac`) y se guardó `tests/interaccion_real_limpio.json`. Las tres respuestas fueron casi idénticas y dieron una explicación incorrecta de attention head; la aplicación ahora advierte esta repetición. **La comunicación LLM es real, pero no se ha demostrado calidad docente ni complementariedad efectiva con este modelo. No es adecuado para uso educativo sin supervisión.** El verificador estructurado comprueba valores concretos; no detecta afirmaciones erróneas expresadas libremente por el LLM. Un modelo más capaz y evaluación humana con rúbrica son necesarios antes de presentar este equipo como tutor fiable. Los agentes son roles de un mismo modelo, no modelos independientes.
